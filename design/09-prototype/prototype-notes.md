# Prototype Notes

## Purpose

This file documents prototype intent, scope, assumptions, and review notes. A prototype can be a Figma file, clickable mockup, coded prototype, or text-based simulation.

## Prototype Scope

| Item | Description |
|---|---|
| Prototype goal | Demonstrate the primary user flow and key states before implementation |
| Fidelity | Low, medium, or high depending on feature risk |
| Source artifacts | User flow, screen specs, style guide, interaction model |
| Reviewers | Product, design, frontend, backend, QA |
| Required states | Default, loading, empty, error, success, permission |

## Prototype Checklist

- [ ] Primary flow is represented.
- [ ] Critical error and empty states are represented.
- [ ] Navigation or route changes are clear.
- [ ] Component usage matches the component map.
- [ ] Accessibility-sensitive interactions are noted.
- [ ] Known limitations are documented.
- [ ] Feedback is captured in the design review report or change log.
